# OpenLinks — обращения поставщикам и проверка WeChat

Расширение Chrome Manifest V3, версия **0.21.0**. Использует аккаунты, уже открытые в том же профиле Chrome. Первый блок сохраняет очередь первичных обращений. Второй блок теперь выполняет **только проверку WeChat и формирует отчёт**: Claude, товар, подготовка и отправка ответов для этого обхода не используются.

Порядок проверки: **1688 → Alibaba → Made-in-China**. На каждой площадке новый проход начинается с верхней строки. Расширение открывает каждый чат, у которого последнее сообщение не старше 24 часов, и ищет сохранённый WeChat ID в тексте сообщений любого участника. Старые результаты не заменяют новое чтение. Чаты с неизвестной датой открываются для её проверки; достоверно старые чаты отмечаются отдельно.

«WeChat найден» означает совпадение ID в прочитанном сообщении. «В тексте не найден» допускается только после подтверждённого чтения всей текстовой истории. Фото, QR-коды и файлы не распознаются. Ошибка чтения — отдельный результат, а не доказательство отсутствия ID. Неполный список или непроверенные чаты останавливают переход на следующую площадку и показывают причину.

Кнопка **«Начать проверку заново»** создаёт новый отчёт и начинает с 1688. **«Пауза»** сохраняет место, **«Продолжить»** возобновляет проход; после ошибки повторяются незавершённые чаты текущей площадки. После полного прохода всех трёх площадок проверка заканчивается. Рабочая вкладка показывается при включённой соответствующей настройке.

## Установка и обновление

1. Распакуйте `openlinks-chrome.zip` в постоянную папку.
2. Откройте `chrome://extensions`, включите **Режим разработчика**, нажмите **Загрузить распакованное расширение** и выберите папку `extension` с `manifest.json`.
3. Для обновления замените файлы в уже установленной папке и нажмите перезагрузку на карточке расширения. **Обновите также вкладки магазинов и чатов**, чтобы загрузились новые контентные скрипты. В версии 0.8.0 добавлено разрешение `debugger` для ввода клавиш в 1688; если Chrome запросит новое разрешение, примите его. Удалять расширение перед обновлением не нужно.
4. Нажмите значок OpenLinks. В «Сообщение и настройки» введите текст и ваш WeChat, сохраните настройки.
5. Добавьте ссылки по одной на строку или импортируйте `.txt`. «Ваши примеры» подставляет 12 ссылок из задачи.
6. При необходимости выберите отдельную папку для `schedule.txt`, `report.txt`, `report.xlsx` и `activity.log`. Оставляйте окно расширения открытым для автозаписи файлов.
7. Запустите очередь. Режим **Подтверждать каждую отправку** позволяет проверить получателя и текст перед нажатием. Его можно выключить для автоматической обработки; неизвестные элементы всё равно требуют обучения.

Обновление сохраняет очередь, историю, лимиты и изученные правила. В первичной очереди включается подтверждение каждой отправки. Выполнение приостанавливается для обновления вкладок. Уже начатая попытка не повторяется. Компьютер должен быть включён, Chrome открыт; спящий компьютер не выполняет очередь. Инкогнито не поддерживается.

## Работа в фоне

Используйте отдельный рабочий профиль с тремя привязанными чатами. В другом браузере или профиле можно заниматься своими делами: ввод на 1688 направлен в конкретную вкладку через `chrome.debugger`, системная клавиатура и буфер обмена для него не используются. В новом блоке диалогов по умолчанию включено **«Показывать рабочую вкладку»**: при обработке расширение переключает активную вкладку на текущую площадку. Для фоновой работы снимите эту галочку. Окно браузера принудительно на передний план не выводится. Для проверки WeChat локальный обработчик Claude не нужен.

Первичная очередь закрепляет своё окно при явном запуске. Новые вкладки создаются неактивными именно в нём; смена вашего активного окна не меняет это назначение. Если окно очереди закрыто, работа приостанавливается до нового явного запуска. Сама площадка при открытии нового чата всё ещё может создать активную вкладку или всплывающее окно. Постоянный мониторинг трёх уже открытых чатов этот путь не использует.

У привязанных вкладок расширение отключает автоматическую выгрузку из памяти, если браузер поддерживает эту настройку. При обычной отвязке возвращается только настройка, которую изменило само расширение. Если она позднее изменена извне, OpenLinks не перезаписывает её на каждом опросе. При обновлении или запуске браузера старые ID вкладок не используются для восстановления; защита прежней открытой вкладки может остаться до её закрытия. Если чат всё же выгружен или заморожен, появляется статус паузы с причиной. История и черновики сохраняются; вкладка автоматически не перезагружается.

Для работы оставьте рабочий браузер и профиль запущенными, а компьютер — без сна. Окно можно убрать на задний план. Замораживание вкладок, сон компьютера или остановка профиля прерывают обработку; точный период 30 секунд не гарантируется браузером. При необходимости добавьте площадки в исключения экономии памяти/энергии. Для автозаписи внешних отчётов оставьте также окно управления открытым. Если сами редактируете рабочий чат, приостановите автоматизацию.

Запускайте автоматизацию OpenLinks только в одном профиле, подключённом к общей папке Claude: данные расширения разделены между профилями, а локальная очередь и настройка модели общие. Проверка установки, Native Messaging и фоновой работы в **Dolphin Anty отложена**; совместимость с ним пока не подтверждена.

## Проверка WeChat — блок 2

1. Откройте второй блок и проверьте сохранённый **WeChat ID**. При необходимости измените его и сохраните.
2. Нажмите **«Открыть чаты площадок»** или **«Начать проверку заново»**: недостающие рабочие вкладки будут открыты автоматически. Авторизуйтесь, если площадка попросит вход.
3. Расширение читает список сверху вниз, подгружая следующие части. На следующую площадку переходит только после подтверждённого завершения текущей.
4. В отчёте для каждого рассмотренного чата отображаются площадка, поставщик, последнее сообщение, результат и время проверки на вашем компьютере. Длинная причина находится под **«Подробнее»**. Доступны фильтры и поиск.
5. При ошибке проверьте её причину и нажмите **«Продолжить»**. Уже полученные выводы текущего прохода сохраняются. Новый WeChat ID требует нового прохода.

Проверка не требует памяти товаров, сообщения продавца, подписки Claude или подключения папки. Старые товары, правила, черновики и настройки Claude сохраняются, но прежние команды подготовки/отправки ответов во втором блоке заблокированы. Первый блок запускается отдельно; автоматического совместного запуска в режиме проверки нет.

При наличии черновика или ввода пользователя обход приостанавливается на текущей площадке. Чужой текст не стирается. Ошибки отдельного чата записываются, после чего проверяются остальные доступные строки этой площадки; при наличии незавершённых проверок переход дальше не выполняется. Неизвестный порядок строк, дата или конец списка не подменяются предположениями.

Отчёт хранится отдельно от прежнего журнала диалогов и не смешивает результаты разных запусков. Лимит — 2000 записей / 2 МиБ; при достижении лимита проверка явно останавливается, сохранённые результаты не удаляются. После перезапуска Chrome проверка остаётся на паузе; рабочие вкладки нужно открыть кнопкой расширения.

### Диагностика чтения в обычном Chrome

Внизу раздела диалогов раскройте **«Диагностика чтения страниц»**, перейдите на диагностическую страницу и нажмите **«Сохранить диагностику»**. Обычная ссылка только открывает страницу: сбор запускается кнопкой. Страница использует существующее разрешение `debugger`, поэтому отдельный Chrome с портом удалённой отладки не нужен. Если DevTools мешает подключению, закройте его во вкладке площадки и повторите проверку.

Перед чтением диагностика ставит очередь первичных обращений на паузу. Она не переключает диалоги, не вводит текст и не отправляет сообщения; после сбора очередь сама не возобновляется. Собирается ограниченное число вкладок и фреймов трёх площадок. `dom` сохраняет очищенную структуру страницы, `snapshot` запускает только чтение адаптером диалогов. Для запуска системной командой можно открыть один из адресов, заменив `ID` идентификатором OpenLinks из `chrome://extensions`:

```text
chrome-extension://ID/diagnostics.html?run=1&mode=dom
chrome-extension://ID/diagnostics.html?run=1&mode=snapshot
```

Параметр `run=1` явно запускает сбор при открытии страницы; без него нужна кнопка. При необходимости `&tabId=123` ограничивает проверку указанной вкладкой. В загрузках Chrome появляется файл `openlinks-diagnostics-…json.gz`. **Это приватный файл: он может содержать имена поставщиков и тексты переписки. Не публикуйте его в GitHub, релизах или общедоступных отчётах.** Значения полей и типовые параметры авторизации исключаются, но это не делает переписку публичной.

Диагностика не заменяет результат проверки WeChat. Отсутствие ID подтверждается только полной текстовой историей; неполное чтение остаётся отдельным статусом в отчёте. Реальные отправки поставщикам в этих проверках не выполняются.

## Новый механизм Alibaba и Made-in-China (0.7.0)

Открытие и распознавание чатов этих площадок переписаны в отдельном `extension/supplier-chat.js` по предоставленному `open-supplier-chat.user.js`. Старый путь поиска/открытия для этих площадок больше не используется.

- **Alibaba:** `a.icbu-alitalk`, `.im-alitalk-container a`, `.icbu-alitalk`. Признак открытия — видимый фрейм `onetalk.alibaba.com` или окно `weblite` / `im-lite` больше 250 × 250 px.
- **Made-in-China:** `a.J-open-tm`, `.webtm-chat-now-tip-button`, `a.tm-placeholder`. Признак открытия — видимый `.webtm-lite-content-visible` или развёрнутый фрейм мессенджера.
- Как в референсе, для каждого селектора выбирается первая видимая кнопка, при её отсутствии — скрытая штатная кнопка. Повторяющиеся штатные кнопки одного шаблона не вызывают обучение. Клик выполняется через `scrollIntoView`, `mouseover` и обработчик самой кнопки. Ссылка `href` не подменяет этот обработчик переходом из фонового процесса.
- Кнопка проверяется каждые 700 мс. Максимум 3 попытки открытия, минимум 5 секунд между ними, общий срок 20 секунд. Это попытки **открыть окно**, а не повторные отправки сообщения. Каждую попытку разрешает и записывает фоновая очередь. При паузе, обучении, удалении строки или переходе к редактору таймер отключается.
- Заранее загруженный скрытый фрейм не считается открытым чатом; его редактор не заполняется. После раскрытия редактор ищется внутри видимого фрейма либо окна чата. В известных документах мессенджеров не требуется угадывать имя класса внешнего контейнера.
- Если чат не открылся за 20 секунд, назначается ограниченная автопроверка. Окно входа и CAPTCHA блокируют отправку; после трёх неудач ссылка пропускается. Бюджет штатных кликов открытия не обнуляется при автопроверке. Для ручного указания элемента доступны кнопки обучения.

**Старые правила кнопки открытия Alibaba/Made-in-China сохранены, но отключены**, чтобы прежний неудачный алгоритм не вмешивался. Они помечены в настройках. Новое обучение получает метку нового механизма и может явно уточнить кнопку. Изученные поля сообщения, кнопки отправки и контейнеры сохраняют применение. Очередь, лимиты, история и механизм 1688 сохраняются.

## Уже открытый чат 1688

Новая вкладка или встроенный фрейм чата завершают этап поиска кнопки 客服. Автоматическая подсказка «покажите кнопку чата» снимается, очередь переходит к редактору. Это работает и при прямом открытии известного чата, и когда новая вкладка сначала была `about:blank`. Если событие открытия пропущено, расширение проверяет связанные вкладки; без связи с исходной вкладкой нужен известный адрес получателя именно этого магазина. При нескольких подходящих вкладках произвольная не выбирается.

Для появления редактора отведено 30 секунд, затем назначается автопроверка. После распознавания пары «редактор + отправка» расширение ждёт полной загрузки основной вкладки и документа фрейма, а затем 5 секунд неизменности элементов. Только после этого вставляется текст и выполняются клик → пробел → Backspace. Если элементы заменились, ожидание начинается заново; суммарно до 60 секунд на попытку подготовки. Ручная пауза и явно включённое обучение останавливают автопроверки. В логе есть события **Открытый чат распознан** и **Ожидание готовности чата**.

## Автоматическая проверка и пропуск ошибок

Для одной ссылки допускается **три неудачные попытки**, между ними **10 секунд**. Неактивная кнопка, сбой ввода, недоступная вкладка или ненайденный элемент запускают проверку той же вкладки. На 1688 она заново выполняет клик в поле, пробел и Backspace. Новое посещение не создаётся; лимиты площадок сохраняются. После третьей ошибки ссылка отмечается «Ошибка — пропущено», причина и история попыток остаются в журнале, начинается следующая доступная ссылка. Таймеры Chrome и сон компьютера могут увеличить паузу.

Подтверждение отправки сохраняется при повторе подготовки того же адреса чата. Изменение адреса, перезапуск браузера, обновление расширения или явное обучение требуют новой проверки. После возможного нажатия отправки автоматического повтора нет. Удаление строки и повторное добавление URL создаёт новую задачу; прежний результат остаётся в журнале.

## После нажатия отправки

Расширение **не ждёт доставки, ответа или прочтения**. На 1688 после заполнения оно через `chrome.debugger` выполняет настоящий клик мышью в поле сообщения, ставит курсор в конец и нажимает пробел, затем Backspace. После клика и пробела есть короткая пауза 100 мс для реакции редактора. Это обновляет состояние редактора, который игнорирует искусственный `keyup`. Проверяется, что исходный текст сохранился; Enter не нажимается. Ввод работает и во фрейме чата. Перед подготовкой существующий текст в выбранном редакторе полностью очищается, затем вводится сообщение из настроек. Это действует для 1688, Alibaba и Made-in-China. Уже вставленный такой же текст 1688 при необходимости активируется заново. Обычная проверка перед отправкой не набирает клавиши заново. Автопроверка после ошибки кнопки и ручное «Проверить снова» повторяют клик и клавиши, даже если черновик уже подготовлен.

Во время этого короткого подключения Chrome может показать полоску отладки. Подключение освобождается после ввода и при ошибке. Закройте DevTools вкладки 1688, если он мешает подключению. Если фокус/текст изменился или ввод недоступен, отправка не выполняется: причина записывается в журнал и назначается автопроверка. При повторной подготовке старый текст также заменяется сообщением из настроек.

В 0.8.2 добавлен настоящий клик мышью: раньше выполнялась только программная фокусировка. Координаты поля определяет Chrome, включая смещение фрейма чата. Проверка текста выполняется после всей последовательности «клик → пробел → Backspace»; промежуточное представление пробела редактором не прерывает эту последовательность. Если фокус ушёл из поля, Backspace не нажимается. Сравнение итогового черновика 1688 учитывает обычные и неразрывные пробелы (`&nbsp;`). Изменённый итоговый текст не отправляется. В логе указан этап сбоя; совет про DevTools относится к подключению или командам Chrome.

После единственного нажатия на 1688 до 1,2 секунды проверяется только локальная реакция: очистилось ли видимое поле сообщения. Если текст остался, чат исчез или связь с вкладкой потеряна, задача получает `attempt_unknown`: **нужна ручная проверка, автоматической повторной отправки нет**. Чат остаётся открытым, очередь переходит к следующей ссылке. Для старых сохранённых задач `uncertain` доступны прежние ручные действия проверки результата.

- `attempted` / **Кнопка отправки нажата** — нажатие выполнено; для новых попыток 1688 также проверено очищение поля.
- `attempt_unknown` / **Нужна проверка — без повтора** — результат попытки неизвестен на любой площадке. В журнале это ошибка, не успешная отправка.
- `retry_wait` / **Ожидание автоматической проверки** — ошибка произошла до нажатия; через 10 секунд проверяется та же вкладка.
- `failed` / **Ошибка — пропущено** — три ошибки на одной ссылке; очередь продолжает работу.
- `sent` — ручное подтверждение пользователем наличия сообщения либо отметка из старой истории.

Очищение редактора — локальная реакция интерфейса, **не подтверждение приёма сервером**. Alibaba и Made-in-China сохраняют режим перехода после нажатия без ожидания результата. Лимит и стадия попытки сохраняются до нажатия, поэтому перезапуск не вызывает дублирование. В логе отдельно видны способ ввода, нажатие, очищение редактора или причина остановки.

**Вкладка чата закрывается через 10 секунд** после завершённого нажатия отправки (`attempted`) или вашего подтверждения наличия сообщения (`sent`). Пока идёт отсчёт, очередь может перейти к следующему магазину. Для чата в новой вкладке закрывается именно эта вкладка; для встроенного чата — содержащая его вкладка. Ожидание проверки, обучение, автоматический пропуск после ошибок и неопределённая попытка не запускают закрытие. Если вы взаимодействовали со страницей, начали новый черновик, перешли на другой адрес или привязали вкладку к новой задаче, закрытие отменяется. После перезапуска браузера старые таймеры теряют право закрывать вкладки. Таймер страницы будит фоновый процесс, `chrome.alarms` страхует его; сон компьютера и ограничения таймеров Chrome могут задержать закрытие. Назначение, выполнение и отмена видны в журнале.

## Обучение по действию пользователя

Если элемент не найден или найден неоднозначно, причина видна в карточке и журнале. Во время автоматических попыток можно включить обучение — это приостановит очередь и покажет подсказку на странице. На текущей карточке доступны кнопки:

- **Показать кнопку чата / 客服** — указать, чем открыть диалог.
- **Показать поле сообщения** — указать сам редактор.
- **Показать кнопку отправки** — указать нужную кнопку и выполнить одну попытку отправки.
- **Показать область диалога** — указать общий контейнер редактора и кнопки, если он не определился автоматически.

Нажмите нужный элемент в магазине или во фрейме чата. Обучающий клик перехватывается: расширение сначала сохраняет правило, затем открывает чат либо готовит сообщение. При обучении отправке нажатие воспроизводится после сохранения и проверки лимита; оно считается вашим подтверждением отправки. Значения полей и текст переписки в обучающие правила не копируются. Если в найденном редакторе уже другой текст, он очищается и заменяется сообщением из настроек. Событие **Старый текст в поле заменён** сохраняет только факт замены; сам старый текст в лог не записывается. Другие поля страницы не очищаются.

Обучение сохраняет основной и запасные CSS-селекторы, тип элемента, короткую подпись кнопки и область применения в `chrome.storage.local`. Правила переживают закрытие окна, перезапуск Chrome и обновление расширения. Новое обучение сохраняет альтернативные шаблоны, а не заменяет все правила того же поля. До 500 вариантов хранятся без автоматического удаления; при заполнении списка нужно удалить ненужные правила в настройках. Витрины с именованными и числовыми поддоменами 1688 используют общую область магазинов; служебные страницы и чат `air.1688.com` имеют отдельную область. Старые правила именованных витрин переносятся автоматически. Также исправлен перенос правил между `*.trustpass.alibaba.com`: прежняя привязка к одному магазину расширяется при обновлении, без потери правил. Витрины `*.en.alibaba.com` и TrustPass имеют отдельные области. В журнале видно, сколько правил сохранено, какие применились и почему другие не подошли. Если изученные поле и кнопка найдены однозначно, контейнер определяется по ним заново, чтобы переносить изменения обёртки страницы. Правила для витрин могут использоваться на других магазинах той же площадки; правила фрейма ограничены наблюдавшимся хостом и разделом адреса. Это локальные правила интерфейса: они могут устареть после обновления сайта. Неверное или неоднозначное правило не даёт разрешения выбирать произвольную кнопку — покажите элемент повторно. В настройках есть список правил с кнопкой **Забыть**. Для сложного интерфейса доступны необязательные ручные CSS-селекторы.

Новое обучение кнопки открытия Alibaba/Made-in-China запускает новый ограниченный цикл открытия. После распознавания открытого окна эта кнопка больше не нажимается. Для сообщения и отправки по-прежнему используются отдельные правила; обучение не записывает текст переписки.

Подсказка снимается кнопкой **Отмена**, паузой или завершением обучения. Обычные клики вне режима обучения не записываются. Формы Inquiry/запросов не обучаются как чат и не отправляются. Закрытые Shadow DOM, неподдерживаемые домены и canvas-редакторы могут потребовать отдельной доработки.

## Alibaba и 1688

**Alibaba.** В предоставленных исходниках кнопка `send-tool-button gray` не имеет `disabled`. Класс цвета `gray` больше не считается запретом нажатия. Проверяются настоящий `disabled`, `aria-disabled`, видимость и `pointer-events`. Распознаются «Пообщаться сейчас», «Chat Now!», редактор `send-textarea` внутри `send-box-container` и штатная кнопка отправки.

**1688 — 客服.** Распознаются `pcV2WangWang` и видимый текст **客服** в обычных элементах страницы. После закрытия препятствия «Проверить снова» возвращает задачу к поиску контакта на витрине, а не пропускает этот этап.

**1688 — окно проверки.** В присланном HTML известное окно `.J_MIDDLEWARE_FRAME_WIDGET` содержит небольшой штатный крестик и iframe проверки. Расширение нажимает этот видимый крестик **при каждом появлении окна**, в том числе на этапе подтверждения отправки, затем заново проверяет страницу. Если один и тот же крестик дважды не закрыл окно, очередь останавливается, чтобы избежать бесконечных кликов. Оно не удаляет iframe или защитные элементы из DOM и не имитирует успешное прохождение проверки. Если препятствие остаётся или окно другое, требуется ваше действие.

**Новая вкладка.** Чат, открытый из вкладки поставщика, подхватывается отдельно, в том числе когда сначала появляется `about:blank`, а адрес приходит позже. Посторонние вкладки без связи с текущей задачей не присоединяются автоматически. Если сайт скрыл `opener`, нажмите **Найти вкладки чата**, выберите нужную и **Использовать выбранную вкладку**. Перед этим проверьте получателя.

**Прямой переход 1688 — общий механизм для всех магазинов.** Поддомен витрины и имя получателя 旺旺 — разные идентификаторы. В предоставленных исходниках связь находится в `window.pageData`: `globalData.domain` указывает магазин, `globalData.sellerLoginId` — продавца, а `components.*.moduleData.commonUrl.wangWangUrl` содержит готовый адрес чата. При отсутствии готовой ссылки адрес строится с `touid=cnalichn<sellerLoginId>`. Данные читаются как JSON; код страницы в фоне не исполняется. Специальных правил для примера `keyangjixie` нет.

- Для известного магазина чат открывается сразу, **без запроса к витрине**. Связь хранится по домену магазина, поэтому смена раздела, параметров URL или перезапуск Chrome её не теряет. Прежние записи, сохранённые по полному URL, также учитываются.
- Для нового магазина выполняется один фоновый запрос к его главной странице с текущей авторизацией. Если HTML содержит однозначного получателя этого магазина, сразу открывается чат, без открытия витрины во вкладке. Фоновый запрос действительно обращается к сайту; это не способ узнать неизвестного продавца совсем без запроса. Тайм-аут — 6 секунд, размер HTML — до 2 МиБ. Квота проверяется и резервируется **перед** запросом.
- Если данные недоступны, противоречат друг другу или сайт требует загрузки/входа/проверки, открывается витрина и используется **客服**. Расширение связывает её с открывшейся вкладкой чата, в том числе после `about:blank`, перехода в той же вкладке или загрузки внутреннего фрейма. Во фрейме берётся получатель, а для будущего открытия сохраняется адрес полноценного веб-чата.
- Данные подходящей витрины, открытой вами вручную, тоже пополняют локальный список адресов. В настройках раздел **Прямые чаты 1688** позволяет открыть известный чат или забыть связь.

Пара одного магазина не применяется к другому. Идентификаторы покупателя, произвольные поля `loginId`, рекомендации и данные сессии не используются для определения получателя. При нескольких противоречащих адресах расширение переходит к штатному открытию чата. Получение адреса, источник связи, прямой переход и причина возврата к обычному открытию видны в логе. Прямой переход сохраняет установленные лимиты площадки.

## Порядок и ограничения

Очередь обрабатывает по одному магазину, по порядку списка. **Исключение — исчерпанная квота за 20 минут:** эта площадка временно пропускается, обрабатываются доступные следующие площадки, затем очередь возвращается к первой отложенной строке, когда квота освобождается. Внутри одной площадки порядок сохраняется. Обычный интервал и заданное время сами по себе не разрешают обгон. Если свободных площадок нет, очередь ждёт ближайшего допустимого времени.

| Площадка | Максимум за скользящие 20 минут | Интервал по умолчанию |
| --- | --- | --- |
| 1688 | 7 | 180 секунд |
| Alibaba | 3 | 420 секунд |
| Made-in-China | Числовой максимум не задан | 60 секунд |

Настраиваемая пауза действует только между **соседними фактическими посещениями одной площадки**: Alibaba → Alibaba ждёт, Alibaba → 1688 → Alibaba — без этой паузы. Лимиты 7/20 и 3/20 сохраняются при любых переключениях. При исчерпании квоты Alibaba → Alibaba → 1688 → Made-in-China очередь временно перейдёт к 1688 и Made-in-China, затем вернётся к первой Alibaba. Перед посещением проверяются квоты посещений и отправок. Отправка отдельно проверяет свой лимит без дополнительного настроенного интервала. Если квота исчерпалась после подготовки сообщения, вкладка сохраняется, очередь обрабатывает другие площадки, затем повторно проверяет тот же чат и выполняет отправку без нового посещения. После перезапуска Chrome или обновления расширения для такого отложенного чата нужно заново выбрать вкладку: старый номер вкладки не используется для отправки.

Резерв до открытия страницы/попытки нажатия сохраняется при ошибке, паузе, ручном повторе и удалении строк. Учитываются только действия этого расширения в этом профиле. Ручные обращения, другие устройства и все HTTP-запросы, которые делает сама страница, расширение не считает. Числа 7/3 предоставлены пользователем; соблюдение этих чисел не гарантирует отсутствие блокировки.

Интервал настраивается от 30 до 86 400 секунд. Входной `.txt`:

```text
# Ссылка на строку; необязательно с заданным временем ISO 8601
https://jcnyjxsb.en.alibaba.com/
2026-11-01T09:00:00+08:00 https://13153773601.1688.com/
```

**Пропустить** сразу закрывает уже открытые вкладки магазина и его чата, связанные с этой задачей; ждать 10 секунд не нужно. Это работает и для чата, отложенного из-за лимита. Ещё не открытая ссылка просто помечается пропущенной. В журнале видно закрытие или причину, по которой вкладка осталась открыта (например, другой адрес, использование другой задачей или необходимость привязки после перезапуска). История и лимиты сохраняются. Пока выполняется нажатие отправки, пропуск недоступен.

У каждой строки есть **Удалить**. Можно выборочно убрать ожидающую, завершённую или остановленную задачу, а затем добавить ту же ссылку заново в конец очереди. История, изученные правила и лимиты остаются. Удаление текущей задачи также снимает её обучение, не закрывая вкладку. Пока выполняется нажатие отправки, удаление недоступно. Дубли нормализованных ссылок, пока они присутствуют в очереди, не добавляются. Разные ссылки одного продавца могут не распознаться как дубль. При импорте экспортированного расписания берутся только строки `pending`. План времени приблизителен: загрузки, обучение, подтверждения пользователя и таймер Chrome могут сдвигать его.

## Логи и хранение

В разделе **Журнал работы** есть таблица результатов: отработавшие ссылки, ошибки / нужна проверка, ожидающие и пропущенные. Поиск работает по адресу и причине; кнопка **События** открывает историю конкретной задачи. Повторное добавление того же URL показывается отдельной строкой. Успешная повторная подготовка сохраняет число прежних ошибок.

- `activity.log`: действия, найденные элементы, причины решений, обучающие этапы и сохранённые правила.
- `report.xlsx`: настоящий Excel-файл с листами **Результаты** и **События**, фильтрами, закреплённой первой строкой, кликабельными ссылками и выделением результатов цветом. Даты — значения Excel, их можно сортировать и фильтровать. Файл скачивается кнопкой **Скачать Excel .xlsx** в журнале или обновляется в выбранной папке.
- `report.txt`: сначала результаты по каждой ссылке (ID задачи, статус, число ошибок, время, причина), затем полная история событий.
- `schedule.txt`: ссылка, площадка, статус и оценка времени.
- Время во всех отчётах и интерфейсе соответствует часовому поясу компьютера, на котором работает Chrome. В Excel пояс и смещение UTC указаны отдельно; TXT/LOG и расписание используют местный ISO 8601 со смещением, например `2026-10-16T08:15:30.000+08:00` для Asia/Irkutsk. Импорт расписания сохраняет исходный момент времени. Часовой пояс не фиксируется в коде; переходы на летнее время учитываются.

Файлы обновляются при изменении состояния и примерно каждые 30 секунд, пока открыто окно управления. При его закрытии очередь может продолжать работать, а внешние файлы обновятся после открытия окна и проверки разрешения папки. Источник состояния — `chrome.storage.local`. Все файлы можно скачать вручную. JSON-снимок включает очередь, сообщение, правила и историю для диагностики; импорт JSON не реализован.

Данные и обучение основной очереди хранятся локально, без внешней аналитики/моделей. Отправка происходит через страницы площадок. История в TXT/JSON полная, в окне показываются последние 500 событий под фильтром. Не удаляйте расширение или его данные в ходе работы: это удаляет историю и счётчики.

Разрешения основной очереди: `storage` — состояние, `alarms` — очередь и закрытие вкладок, `webNavigation` — поиск в доступных фреймах, `debugger` — краткое подключение только к активной задаче 1688 для клика в редактор и событий Space/Backspace, доступ к доменам трёх площадок — работа с интерфейсом. Код ввода не выполняет команды страницы, не перехватывает сеть и не использует буфер обмена. Чужие файлы `activity.log` и `report.xlsx` не перезаписываются при восстановлении папки без явного согласия на замену. Отдельные режимы мониторинга, ИИ-черновиков и диагностического чтения описаны выше.
