# OpenLinks — очередь обращений к поставщикам

Расширение Chrome Manifest V3 с отдельным окном управления на русском языке. Использует уже открытые сессии ваших аккаунтов; пароли и токены вводить в расширение не нужно. Сборка и сервер не нужны.

Это первая версия, проверенная на локальных формах. Адаптация к реальным авторизованным интерфейсам 1688, Alibaba и Made-in-China ещё требует проверки в вашем Chrome. Нельзя гарантировать отсутствие блокировки или безошибочную работу с любой будущей версией сайта.

## Установка и первый запуск

1. Распакуйте `openlinks-chrome.zip` в постоянную папку. Не удаляйте её после установки.
2. Откройте `chrome://extensions`, включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение**, выберите папку **extension**, содержащую `manifest.json`.
4. Если магазины были открыты до установки, обновите эти вкладки. Войдите в аккаунты на площадках в том же профиле Chrome. Режим инкогнито не поддерживается.
5. Нажмите значок OpenLinks. Откроется отдельное окно.
6. В **Сообщение и настройки** введите текст, включая ваш WeChat, и сохраните настройки. Начните с включённого **Подтверждать каждую отправку**.
7. В очереди вставьте ссылки или импортируйте `.txt`. Кнопка **Ваши примеры** подставляет 12 ссылок из этой задачи; их нужно отдельно добавить в очередь.
8. При необходимости выберите отдельную папку для `schedule.txt` и `report.txt`. Существующие файлы заменяются только после подтверждения. Оставьте окно управления открытым для автозаписи.
9. Нажмите **Запустить очередь**. Магазин откроется в новой вкладке. Когда форма подготовлена, **откройте вкладку и проверьте получателя и текст**, затем нажмите **Подтвердить и отправить** в окне управления.

Расширение само отправляет сообщения только после запуска пользователем. При разработке продавцам ничего не отправлялось. Для работы компьютер должен быть включён, Chrome открыт и иметь доступ к Интернету; спящий компьютер не выполняет расписание.

## Очередь, лимиты и время

| Площадка | Максимум за скользящие 20 минут | Интервал по умолчанию |
| --- | --- | --- |
| 1688 | 7 | 180 секунд |
| Alibaba | 3 | 420 секунд |
| Made-in-China | Числовой максимум не задан | 60 секунд |

Интервалы настраиваются от 30 до 86 400 секунд. Лимиты 7/3 нельзя отключить уменьшением интервала. Счётчики отдельно ограничивают начало посещений магазинов и попытки отправки. Резерв сохраняется **до** открытия страницы и **до** нажатия кнопки; ошибка, пауза и очистка ожидающих задач его не отменяют. Учитываются только действия этого расширения в этом профиле Chrome, а не ваши ручные обращения или другие устройства. Числа 7/3 предоставлены пользователем, их нельзя считать гарантией безопасности или подтверждёнными правилами площадок. Страница сама может делать много HTTP-запросов: расширение ограничивает контактные операции, а не все сетевые запросы браузера.

Обрабатывается один поставщик за раз. Если площадка ждёт своего интервала, может быть выбран доступный поставщик другой площадки. Расписание показывает предварительную оценку; ручное подтверждение, загрузки, капчи и отдельная пауза перед отправкой могут сдвинуть фактическое время. Таймер `chrome.alarms` может сработать позже назначенного срока; лимиты всё равно проверяются перед действием.

Формат входного `.txt` — ссылка на строку, необязательно с временем ISO 8601 с часовым поясом:

```text
# Комментарий
https://jcnyjxsb.en.alibaba.com/
2026-11-01T09:00:00+08:00 https://13153773601.1688.com/
https://yiyueda.en.made-in-china.com/
```

Одинаковые нормализованные ссылки, в том числе уже обработанные, повторно не добавляются. Метки `spm`, `utm_*`, `tracelog` и фрагмент URL не участвуют в сравнении. Разные ссылки на одного продавца могут не распознаться как дубль: проверяйте список самостоятельно. Из экспортированного расписания импортируются только строки со статусом `pending`; завершённые и неоднозначные попытки автоматически не повторяются.

## Что происходит при ошибках

- **CAPTCHA, вход в аккаунт, ограничение сайта:** очередь останавливается. Выполните необходимое действие вручную в созданной вкладке, затем нажмите **Проверить снова**. Капчи не решаются и не обходятся автоматически. Ошибки сервера и неизвестная верстка могут также требовать ручной проверки.
- **Несколько контактов или полей:** расширение не выбирает произвольное. Откройте нужный чат в той же вкладке и повторите проверку либо пропустите задачу и настройте селекторы.
- **Другой черновик в поле:** он не перезаписывается. Уберите его или сохраните самостоятельно перед повторной проверкой.
- **Обязательные поля темы, товара, e-mail:** заполните вручную. Расширение не придумывает значения и не принимает условия от вашего имени.
- **Нет подтверждения после нажатия:** через 45–75 секунд статус становится **Отправка не подтверждена**, очередь останавливается. Проверяйте чат вручную; затем выберите **Проверил: сообщение отправлено** либо **Пропустить поставщика**. Автоповтора нет. После этого очередь запускается отдельной кнопкой.
- **Нажата пауза:** новые действия не начинаются; уже выполняющееся нажатие нельзя отменить. При возобновлении проверяется его результат, без повторного нажатия.
- **Перезапуск Chrome:** выполнение приостанавливается для проверки вкладки и возможной отправки. Завершённая история и лимиты сохраняются. Прерывание только service worker не должно вызывать повторную отправку: её стадия сохранена заранее.
- **Контакт доступен только в AliWangWang или другом внешнем приложении:** расширение не управляет такими программами. Нужен доступный веб-чат площадки; при его отсутствии задача требует ручной обработки.

## Поиск элементов и автоматический режим

По умолчанию используются видимые поля `textarea`/`contenteditable`, смысловые подписи контакта и отправки на английском, китайском и русском. Проверяются доступные фреймы в доменах площадок и открытые Shadow DOM. Автопоиск не использует случайные номера классов, но не покрывает все варианты интерфейсов. Закрытые Shadow DOM, неподдерживаемые домены чатов, canvas-редакторы и нестандартные формы требуют отдельной доработки.

Для каждой площадки можно задать четыре **CSS-селектора**:

1. Кнопка/ссылка контакта на странице магазина.
2. Поле сообщения в веб-чате/форме.
3. Кнопка отправки.
4. Подтверждение успеха, которое **впервые появляется после отправки** и содержит непустой текст.

Селектор контакта, редактора и отправки должен находить ровно один видимый элемент в соответствующем документе. Проверьте его в DevTools на реальной странице: `document.querySelectorAll('ВАШ_СЕЛЕКТОР')`. Статический блок, общий контейнер страницы или кнопка «Отправить» не подходят в качестве подтверждения успеха. Не используйте приведённые ниже демонстрационные селекторы на реальном сайте без проверки:

```text
Контакт:       a[data-action="contact-supplier"]
Сообщение:     textarea[name="message"]
Отправка:      button[data-action="send-inquiry"]
Успех:        [role="status"].inquiry-success
```

Сначала вручную проверьте первый контакт на каждой площадке в режиме подтверждения. Для автоматического режима необходимо задать все четыре селектора на каждой площадке, присутствующей в очереди, и выключить подтверждение. Само наличие селекторов не доказывает их правильность: выбор получателя и проверка адаптации остаются обязательными. Автоматический режим также останавливается при неоднозначности, капче или отсутствии подтверждения.

Старый баннер успеха не подтверждает новую отправку. При автопоиске учитываются новые явные уведомления об успехе либо новые исходящие сообщения в распознанных контейнерах чата. `sent` означает наблюдаемый признак в интерфейсе или ручную отметку пользователя, а не подтверждение серверной доставки/прочтения. Если сайт не даёт распознаваемого признака, результат остаётся неподтверждённым.

## Файлы, хранение и разрешения

- `schedule.txt`: ISO-время в UTC, площадка, статус и ссылка; обновляется после изменений и примерно каждые 30 секунд при открытом окне.
- `report.txt`: события посещения, подготовки, попытки отправки, подтверждения, остановки и пропуска с фактическим временем UTC.
- Интерфейс показывает локальное время компьютера. Время в `.txt` однозначно задано суффиксом `Z`.
- Если окно управления закрыто, очередь может продолжать работать, но внешние TXT-файлы не обновляются до открытия окна. Источником состояния остаётся `chrome.storage.local`. При следующем открытии файлы синхронизируются, если Chrome сохранил разрешение папки; иначе выберите её снова.
- Ручное скачивание обоих файлов доступно без выбора папки. JSON-снимок содержит тексты, очередь, историю и лимиты для просмотра/диагностики; автоматическое восстановление из JSON не реализовано.
- В интерфейсе показываются последние 500 событий; TXT/JSON содержат всю сохранённую историю. Не удаляйте расширение и его данные в ходе рассылки: это удаляет историю и счётчики. При исчерпании локальной квоты дальнейшая отправка не должна начинаться, поскольку предварительная запись не удастся.
- Данные не уходят на сторонний сервер: нет аналитики, облачной синхронизации или внешних библиотек. Сообщения отправляются только через страницы площадок. TXT/JSON содержат вашу переписку/контактные данные: храните папку соответственно.
- `storage` хранит состояние; `alarms` пробуждает очередь; `webNavigation` позволяет искать форму во фреймах; доступ к трём доменам нужен для чтения интерфейса и взаимодействия с ним. Не запрашивается доступ ко всем сайтам.

## Разработка и проверки

Структура: `extension/background.js` — последовательный координатор и сохранение; `extension/lib/core.js` — лимиты, очередь и экспорт; `extension/content.js` — поиск, заполнение и отправка; `extension/dashboard.*` — отдельное окно; `extension/lib/files.js` — File System Access и скачивание.

Из корня репозитория, Node.js 20+ (проверено на 24):

```sh
npm test
npm run check
```

Внешние npm-зависимости отсутствуют. Для браузерных проверок нужен Python 3.10+, Playwright и установленный Chromium:

```sh
python -m venv /tmp/openlinks-test-venv
/tmp/openlinks-test-venv/bin/pip install -r requirements-dev.txt
CHROMIUM_PATH=/usr/bin/chromium /tmp/openlinks-test-venv/bin/python tests/browser_test.py
```

Браузерный тест запускает локальный сервер и подменяет страницы поставщиков локальными HTML-фикстурами; продавцам он не пишет. Он исполняет настоящий код интерфейса, контентного скрипта и файловых операций. Транспорт Chrome API заменён тестовым. Тесты координатора также используют тестовый Chrome API. Скриншот сохраняется в `test-results/dashboard.png`.

В этой облачной среде политика Chromium запрещает установку распакованных расширений; проверить всю установленную MV3-связку здесь не удалось. Реальные сайты из примеров также недоступны через сетевой прокси (403). Браузерные фикстуры не подтверждают совместимость с текущими авторизованными формами площадок. Для приёмки нужен запуск распакованного расширения в вашем Chrome с одним проверяемым поставщиком на каждой площадке.
